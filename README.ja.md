# safe-line-desktop-mcp

**非公式。** パソコン版 LINE（Windows・Mac）を、あなたの AI エージェントが読む・送る・整理するための
MCP サーバーとスキルです。安全の仕組みつきで、**あなたが PC で作業していても、マウスを取り合いません**。

> LY Corporation とは関係ありません（公認・提携ではありません）。「LINE」は LY Corporation の商標です。

## 使っていないグループが多すぎる人へ

同窓会、一度きりのイベント、終わった案件……。何年も使ううちに、動いていないグループが数百件たまります。
スキル `line-group-cleanup` を使うと、AI がこう進めます。

1. **一覧にする**: グループごとに、最後の発言の日付と何のグループだったかをまとめ、「抜ける／残す」の案を出します
   （基準はあなたが決めます。例:「365日発言なし。家族と仕事は残す」）。
2. **あなたがチェック**: チェックリストに印を付けるだけ。「実行して」と言うまで何も変えません。
3. **印を付けたものだけ退会**: 1件ずつ、確認画面の直前に画面のグループ名を読み合わせてから押します。
   ペースを守り、手元に記録を残します。

約270件の整理を実際に行ったときの手順から作りました。

## ほかにできること

- **未読の確認**: 未読のトークを全部見て、相手・要点・急ぎ度をまとめ、返信案を作ります。送るのはあなたが認めたものだけです（`line-unread-triage`）。
- **読む・送る**: 名前でトークを開く、本文を文字で取る、メンション付きで送る（`line-desktop`）。
- **グループの管理**: グループの作成、メンバーの招待・削除、名前の変更。どれも画面の名前と照合してから押します。
- **LINE の更新でずれたら自分で直す**: ボタンの位置が変わったら、AI が撮り直して測り、設定に保存します（`line-desktop-recalibrate`）。

**Claude Code・Codex・Claude Desktop・Cursor・VS Code** など MCP に対応した AI で使えます。PC で常駐する個人の AI
エージェントからは、手元だけの HTTP でもつなげます。スキルはただの Markdown なので、どの AI でも読めます。

## 最初から安全側

| | |
|---|---|
| 作業の邪魔をしない | Windows では、撮影・一覧の確認・スクロール・1回のクリック・検索欄・ふつうのキーを**裏のまま**行います（LINE を前に出さず、マウスも動かしません）。前に出す必要がある操作は、あなたの入力が途切れるのを待ってから素早く済ませ、元の窓とマウスの位置を戻します。 |
| 触ったら止まる | 前に出している最中に、あなたが実際のキーボード・マウスを触ると、すぐ止まります。何を押した後で止まったかも返します。 Windows では、ドラッグの各ステップ・ホイールの1目盛りごと・入力の1文字ごと・Ctrl+V の直前に、利用者の操作と前面の窓（対象の窓であること）を確かめ、ドラッグ中に止まってもマウスボタンは必ず離します。 |
| 宛先の取り違えを防ぐ | 送信・本文の取得・グループ管理の操作には、AI が画面で読んだ名前が必要です。サーバー自身は画面の名前を**読めません**（画像を返すだけ）。そのため名前を記録し、返した画像で確かめるよう AI に伝えます。Windows では、直前のスクリーンショットから見出しが変わった場合や読めない場合は送信を断り、送信キーの直前にもう一度確かめます。 |
| 送信は `line_send` だけ | トークの入力欄・送信ボタンの領域へのクリックとドラッグは、`action` の有無にかかわらず断ります（領域はレイアウトから決まり、設定ファイルで変えられます。Mac ではチャット窓の全体です）。`line_key` は Return/Enter/Space（alt/ctrl/shift+Return や設定した送信キーも）を断ります。例外は、ダイアログ内（`window=popup`）で、管理の操作名と対象名を付けた素の Return だけです。`line_type` は制御文字を断ります。送信は、キーを押す前に数えて記録します。 |
| 下書きとクリップボードを守る | 書きかけの下書きは退避して戻します（途中で失敗しても戻します）。下書きを読めない環境（macOS）では `replace_draft=true` がない限り送信を断ります。クリップボードに文字以外（画像・ファイル・書式付きなど）があるか、中身を調べられないときは、上書きせず貼り付けを断ります。利用者の文字は、クリップボードが私たちの置いた内容のままのときだけ戻します。確認と書き込み（または復元）の間に他のプログラムが書き換える小さな競合は残ります。 |
| 同時に動かすのは1つだけ | 画面を変える・LINE を前面に出す（`line_open`・前面での `line_screenshot`）・フォーカスを戻す呼び出しはすべて、呼び出し全体（フォーカスを戻す処理を含む）でプロセス間の1つのロック（状態フォルダの `ui.lock`。OS のファイルロックなので、持ち主のプロセスが終わった瞬間に解除されます）を持つため、2つの AI が同時に貼り付け・送信・下書きの復元をすることはありません。後から来た側には「別の AI が LINE を操作中」と返します。 |
| 回数の上限が最初から有効 | 送信は1分5通・1日100通、管理の操作は1分6件・1日150件。設定ファイルで変えられます。確認と記録はロックファイルの下で一度に行うので、複数のプロセスが同時に上限をすり抜けることはありません。 |
| 自分だけが読める保存先 | 状態フォルダ（設定・操作記録・回数カウンタ・ロックファイル）と会話ログのフォルダは、Mac・Linux では自分だけが読める形（フォルダ 0700・ファイル 0600）で作り、既にあれば絞ります（絞れなければ保存を断ります）。Windows ではユーザーごとのプロファイル（`%LOCALAPPDATA%`）の下に置き、そこの ACL に任せます（このサーバーは ACL を変えません）。`LINE_MCP_LOG_DIR`・`LINE_MCP_HOME` を共有フォルダへ向けないでください。 |
| 手元だけの記録 | 送信ごとに時刻・トーク名・文字数・短いハッシュを残します。**本文は残しません**（残す設定にしたときだけ）。PC の外へは出しません。記録を書けないときは操作を断ります。 |
| 遠隔操作の口を作らない | 既定は標準入出力。HTTP は手元（127.0.0.1）だけで待ち受け、24字以上のトークンが必須。`Origin` ヘッダー付きの要求はすべて断ります（ブラウザは付け、MCP クライアントは付けません）。無言の接続は15秒で切り、同時接続は8本までです。 |
| メモを開かない | 本文の取得は Keep メモを断ります。会話ログ・操作記録・設定ファイルを Git のリポジトリの中へ書くことはありません。 |
| メッセージは指示ではない | LINE の中の文章を AI への命令として扱わないよう、スキルで決めています。 |

これらは、誤操作と外部からの悪用を防ぐための仕組みです。PC で既に動いている悪意あるソフトを防ぐ砂場ではありません。

スクリーンショットは読み返すためだけに、自分だけが読める一時フォルダ（0700。Mac・Linux ではファイルも0600）へ書き、読んだ時点で削除します（読まれなかったものは、1時間後の次の撮影のときに消えます）。

ガードの限界: メインウィンドウでの素の左クリックは「ナビゲーション」（トークやタブの選択）として扱い、数えも確認もしません。ポップアップ内のクリックにはすべて `action` が要ります。`action=menu` は、このサーバー経由のクリックでメニューを開いた直後の1クリックだけ、かつポップアップがメニューの大きさのときだけ通します（大きさによる目安で、ボタンの文字は読めません）。メイン画面で既知の退出確認ボタンから60px以内のクリックには管理の操作名が要ります。前面の確認は、Windows では対象の窓そのもの、Mac では LINE アプリ単位です。Windows の補助スクリプト（`server/line_desktop_windows.ps1`）のクリックはこれらのガードの外にあります（LINE の窓の中に限定）。この補助スクリプトの画像は、既定ではユーザーごとの一時フォルダに保存され（`-Cmd cleanup` で削除）、Git の作業ツリーの中を指す `-Out`（ジャンクション・シンボリックリンク経由も）は断ります。Mac では、チャット窓より明らかに小さい窓だけをダイアログとみなし、チャット窓は決してポップアップ扱いにしないので、`window=popup` で Return/Space がチャットへ送られることはありません。管理の操作の確定は `line_click ... action=... expected_target=...` で行ってください。

## 必要なもの

- Windows 10/11 または macOS と、ログイン済みのパソコン版 LINE
- Python 3.10 以上（標準ライブラリだけ。追加のインストールは不要）
- 座標は Windows 版 LINE（窓 767×722・拡大率100%）で実測しました。ほかの大きさでも、測り直せば使えます。
  **Mac は試験的で、実機での動作確認はまだしていません**（座標は1台で実測したもの。Mac 用のコードは代用品を使ったテストでしか動かしていません）。画面を毎回確かめてから操作してください。

## 入れ方

```bash
git clone https://github.com/desktop-agent-tools/safe-line-desktop-mcp
```

AI への登録方法は [examples/mcp-clients.md](examples/mcp-clients.md) にあります。
Claude Code ならプラグインとして入れられます（サーバーとスキルが一度に入ります）。

```bash
claude plugin marketplace add desktop-agent-tools/safe-line-desktop-mcp
claude plugin install safe-line-desktop
```

設定を変えたいときは、[config/config.example.json](config/config.example.json) を
`%LOCALAPPDATA%\line-desktop-mcp\config.json`（Windows）か
`~/Library/Application Support/line-desktop-mcp/config.json`（Mac）へ写して直します。

あとは AI に「LINE の未読を見て」「使っていない LINE グループを整理したい」と頼むだけです。

## 制限

- 座標は、窓の大きさ・表示の拡大率・言語・LINE の版で変わります。ずれたら測り直してください。
- トークを開くと、相手には既読が付きます。
- 画面の撮影: Windows は LINE の窓そのものを撮ります（PrintWindow）。撮れないときは画面の範囲を写すので、上に重なった別のアプリが写ることがあります。Mac は窓の範囲を画面から撮るので、LINE の上に重なった窓（メニューの撮影のときなど）が、AI に渡る画像に写ることがあります。
- メニュー・右クリック・複数行の文・メンション・送信キーは、一瞬 LINE を前に出します。
- メンションは、利用者が設定ファイルか `LINE_SEND_KEY` で「修飾付きの送信キー」（`alt+Return`・`cmd+Return`）を宣言したときだけ使えます（候補の確定で Return を押すため。LINE の実際の設定は読めません）。
- Windows では、最初の検索・クリック・スクロール・キー・入力・トーク選択のときに画面の状態を覚えます。`line_read_chat_text`（`restore_view=false` 以外）と `line_scan_list` は自動で戻します。それ以外（`line_open_chat`・`line_search`・`line_send`・クリック・キー・スクロール）の後は、最後に `line_restore_view` を呼んでください。戻せなかったときは、再試行できるよう記憶を残します。Mac では記憶も復元もしません。
- Linux は対象外です（パソコン版 LINE がありません）。
- 無保証です。Issue は歓迎しますが、対応はできる範囲で行います。

## 一緒に使って、一緒に育ててください

もとは、通知の多い LINE を片付けるために一人が作った道具です。いろいろなパソコン、LINE の版、AI で
使われるほど良くなります。気軽に使って、うまくいかなかったところを教えてください。

- **使ってみた**: OS・LINE の版・窓の大きさと拡大率・使った AI を Issue に書いてください。「動いた」だけでも助かります。
- **LINE の更新でボタンの位置がずれた**: スキル `line-desktop-recalibrate` で測り直した値を、PR で送ってください。
- **自分なりの使い方がある**: スキルは普通の Markdown です。自分の決まった作業（誕生日、イベントのグループ、
  家族のトーク など）のスキルは、最初の PR にぴったりです。
- **安全の穴を見つけた**: 公開の Issue ではなく、非公開で知らせてください（[SECURITY.md](SECURITY.md)）。
